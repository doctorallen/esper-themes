Esper Themes Palettes & Accessibility

Each theme's colors come from its own palette, generated from the theme files by npm run build:palette-page. The palette data keeps semantic names and hex values together, derives RGB values automatically, and checks color theory separately from text and UI accessibility.

Accessibility thresholds

Color theory describes visual relationships; it does not make a foreground/background pairing readable. The cards below use the relevant WCAG threshold for the role being tested.

UseGuidelineRequired contrastApplied to
Normal textWCAG AA4.5:1Body copy, labels, and syntax text
Normal textWCAG AAA7:1Enhanced readability target
Large textWCAG AA3:1Large headings and display text
UI borders/focus boundariesWCAG 1.4.113:1Controls, separators, and focus rings

Foreground/background text pairs

Each card previews the actual foreground and background roles from the selected theme. A pairing is labeled PASS only when it meets the normal-text AA target; the additional badges show AAA and large-text results.

Main color and border pairs

Borders and focus boundaries are evaluated against their surrounding surface using the 3:1 non-text contrast requirement.

Color-theory recipes

Analogous, complementary, warm/cool, and role-based recipes are useful for composition. A recipe is called text-safe only when its declared foreground/background test passes; otherwise it is explicitly marked accent-only.
