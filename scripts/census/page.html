Esper Theme Census

The 30 most-installed color themes on the Marketplace, 164 million installs between them, measured key by key from their shipped JSON, and Esper's 11 themes measured the same way. The study shows what the field does and where Esper sat; the regrade follows it version by version; the last part documents each Esper theme's palette, its accessibility audit and the color theory behind it. Every theme is rendered as VS Code's Modern UI draws it. Regenerate with npm run build:census-page.

01 · Specimens

Every theme, rendered from its own colors

Each window is drawn as VS Code's Modern UI lays out the workbench: rounded cards on the title-bar ground, the activity rail a card of its own, pill tabs, a filled active activity item, and a pane tab on the terminal. Esper sets the Modern UI keys (surface.*, modernEditorTab.*, modernActivityBarItem.*, modernTab.*); the popular themes do not, so theirs fall back to the matching classic keys. Every token comes from tokenColors plus semanticTokenColors, brackets are colorized as VS Code ships, and the editor is mid-search for ship. Select a window to open its breakdown below.

03 · Workbench vs editor

Grounds and chrome

Nineteen of the top 30 set the sidebar a step darker than the editor and ten paint everything one color; only Visual Studio's C/C++ theme lifts its chrome above the code. Esper lifts it on every dark theme. In v0.11.0 the step reached +0.16 OKLCH lightness over grounds darker than all but two popular themes; the regrade kept the look, capped the step at 0.03, and moved the film grounds to L 0.19, where GitHub Dark, Ayu Dark, Bearded's black variants and Omni sit.

04 · Semantic color

What each role is colored, and how much the field agrees

Each role is a real TypeScript, HTML, CSS or Markdown scope stack resolved the way VS Code does it, with semanticTokenColors overriding names where semantic highlighting is on. Colors are bucketed into hue families by OKLCH hue; under 0.035 chroma counts as neutral. The field's convention: strings green, keywords purple or pink, functions blue, types yellow, numbers orange, and plain variables, properties and punctuation at the foreground. Esper keeps its film palettes for the hues and, since the regrade, the field's habit of leaving variables as text.

05 · Token settings

How the themes are built

Rule counts vary seventy-fold and say little about quality; coverage of grammars beyond TypeScript matters more. Only 9 of the 30 define any semanticTokenColors; every Esper theme defines 32. Esper rows show the themes as they build now.

Coverage counts 16 extra scopes (JSON and YAML keys, Markdown emphasis, diff markup, Python decorators, CSS values, Go imports and others). Near-collisions counts role pairs within ΔE 6 that are not the same color; color-blind merges counts pairs that become one color for a deuteranope or protanope.

11 · Color theory

Recipes in the theme's own colors

Analogous, complementary, warm/cool and role-based recipes are useful for composition. Each is read off the selected theme's palette and given a declared foreground and background; a recipe is text-safe only when that pair clears normal-text AA, and accent-only otherwise, which means fine for large areas, borders and signals but not for text.

12 · Notes and method

How this was measured, and what is still open

Q at runtimeQ's specimen is its static fallback, which mirrors LCARS. The generator draws its editor around L 0.20, fills the new roles from its own palette, retries a draw that cannot reach AA, and always separates its terminal brights; 1,000 seeded draws all succeeded. Its random syntax palette is not yet held to the role-distance checks.
The build enforces itscripts/build-themes.js fails when two syntax roles are different colors within ΔE 6, or within ΔE 3 as a deuteranope or protanope sees them. LCARS is held to the same checks, read off its own rules.
  • Snapshot. The popular themes and the earlier Esper versions are a measured snapshot in docs/census/snapshot.json; the current Esper themes are measured from themes/ by scripts/census/analyze-theme.js each time the page is built.
  • Selection. Marketplace query sorted by installs, category Themes; icon themes and tools listed there were skipped until 30 color-theme extensions remained, from Visual Studio's C/C++ themes (60.2M) to Eva Theme (0.82M). Each VSIX was downloaded and its theme files read directly.
  • Flagship variant. One variant per extension, the one it names after itself or its default dark variant. Thirteen extensions also ship a light variant; those form the light comparison set. Mix is left out of Esper because it is assembled from the others.
  • Token resolution. Each role is a full scope stack matched against every tokenColors selector, descendant selectors included; the deepest match wins, then the most specific, then the later rule. semanticTokenColors override names when semantic highlighting is on. Unset roles fall back to editor.foreground.
  • Color math. WCAG 2 contrast against editor.background; hue, lightness and chroma in OKLCH; collisions as OKLab ΔE × 100. Color blindness is simulated with Machado, Oliveira and Fernandes (2009) at full severity.
  • Limits. Unset workbench keys fall back to VS Code's defaults. The Modern UI rendering is an approximation of VS Code's geometry; popular themes are drawn from their classic keys. Language servers beyond TypeScript can recolor names beyond what is measured here.
